# Result

The service is reachable as an A2A agent: the card validates as a v0.3
`AgentCard` against the official v0.3 JSON schema (Draft 7,
`definitions.AgentCard`) at both well-known paths, with the main
URL/transport repeated in `additionalInterfaces` and the bearer scheme
advertised because a token file was configured. An unauthenticated POST gets
the 401 challenge, and the task methods answer with their spec error codes.

The live `message/send` ran the normal grounded loop: one `search_writing`
tool call, a 986-token prompt, a cited Ghost chunk, and a 3-second wall
clock. The audit line records the token id, question, outcome, iteration
count, citation count, and elapsed time - but not the answer or the excerpt.

Two build notes surfaced here:

* The live binary must be built with `-tags sqlite_fts5`; without it the
  driver reports `no such module: fts5` and the loop fails with `-32603`.
* A token file is needed before `--bind-public` will start, and the file
  must be `0600`. `agent tokens add` creates it that way.
